StateLite fan control: implementation and sources

Scope
StateLite implements its own fixed-purpose fan helper. It does not bundle or call
another fan-control application's helper. AppleSMC is a private interface; the
community observations below are not an Apple compatibility guarantee.

Current control behavior
The app reads fan metadata without administrator rights. A requested custom speed
uses a separately authorized, root-owned helper installed at fixed system paths.
The on-demand service validates the connecting user's kernel audit token, running
code signature and pinned code-directory hash. Application and helper signatures
require hardened runtime without the supported injection/debugging exceptions.
An update that changes the approved code identity requires authorization again.

The protocol accepts only bounded SET, SYSTEM and PING messages. SET includes the
complete fan-ID set; the helper independently checks finite targets against each
fan's reported minimum and maximum. It does not accept arbitrary commands, file
paths or arbitrary SMC keys. One lease owns fan control at a time.

After unlocking when required, the helper writes manual mode before the target.
It retries only transient SMC result 0x82 when the transport succeeded. Mode and
target attempts, observation and bounded replay share a 16-second handoff budget.
All fan modes and targets must match in two consecutive observations before ACK.
ACK confirms those readbacks; actual mechanical RPM can take longer to converge.

PING renews a 10-second lease, including during a pending handoff. An ACK is not a
heartbeat. SYSTEM, EOF, lease expiry, parent-process loss, handled termination
signals and sleep trigger restoration attempts. Restoration requests automatic
mode and releases Ftst, allowing bounded time for consistent system-ownership
readbacks. It never clears target RPM while ownership could still be manual.

A recovery marker is created before a control session and removed only after
confirmed restoration. A later service startup with a marker attempts recovery
before accepting control. Idle helpers exit; there is no idle hardware polling or
control heartbeat. The GUI does not automatically reacquire manual mode on wake.

Verification and limitations
The 0.4.3 acceptance recorded short 3500-RPM operation of both fans on an M4 Pro,
actual RPM convergence, successful return to system control, and reuse from a new
app process without another authorization prompt for the same installed build.
Mock tests cover rejected writes, delayed readbacks, shared time budgets, malformed
requests, stale acknowledgements, lost leases, and recovery success/failure.
Socket tests exercise actual audit-token/signature validation without SMC writes.
These scopes are distinct; mocked recovery is not real-device recovery evidence.

Cross-reboot reuse, extended operation, actual sleep/crash recovery, uninstall and
other Mac models have not been established by that acceptance. Synchronous IOKit
calls, process termination and power loss prevent a guaranteed recovery deadline.
Ad-hoc signing is not Apple notarization or a publisher identity. Installation,
upgrade and removal currently use deprecated AuthorizationExecuteWithPrivileges;
that initial installation mechanism is not claimed to resist every same-user
malicious modification. Fixed RPM is not a replacement for system thermal policy.
